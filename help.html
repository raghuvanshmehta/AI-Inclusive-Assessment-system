Platform Guide & AI Integration Architecture

The AI Inclusive Assessment System is built from the ground up to empower diverse learners through sensory, visual, and cognitive accommodations.

1. Understanding the Four Learner Categories

👤 No Special Need

The standard interface for students without specific accommodations. All personalization options (contrast, font resizing, read-aloud) remain accessible at any time.

👁️ Low Vision

Optimized for visual clarity. Automatically activates an ultra-high-contrast palette (white on black with high-visibility accents), enlarges text up to 22px, and enables the Read-Aloud speech toolbar.

⚡ ADHD (Attention Deficit Hyperactivity)

Structured for distraction reduction and pacing. Implements a one-question-at-a-time focus view, eliminates sliding animations, provides an uncluttered canvas, and triggers optional gentle recharge breaks every 5 questions.

📖 Dyslexia

Designed for fluid typographic comprehension. Uses specialized weighted letterforms, increases line spacing to 1.9x, applies relaxed word and letter spacing, left-aligns text to prevent river effects, and provides clear option separation.

3. Trained AI Model Context & Backend Roadmap

Integration details for the predictive knowledge tracing model.

ASSISTments 2012-2013

The AI Inclusive Assessment System includes a machine learning model trained on the ASSISTments 2012–2013 educational dataset (285,762 student interactions, 10,709 unique students). In the repository, the model weights and pipelines are preserved in final_model_2012.joblib and model_package_2012.joblib.

Historical Evaluation Metrics

  • Test AUC: approximately 0.7258
  • Test Accuracy: approximately 0.7300 (vs 0.6934 guessing baseline)
  • Slow-Paced vs Standard Group AUC: 0.709 (slow top 25%) vs 0.730 (standard 75%)
Note: These are verified experimental metrics from the research evaluation. They predict student correctness likelihood on prospective problems and do not automatically generate raw questions.

Backend API Integration Endpoints

When a backend service (e.g. FastAPI / Flask / Node) is connected, the frontend module js/api.js is pre-wired to communicate via the following REST contract:

HTTP Method Endpoint Purpose & Payload
POST /api/auth/login Authenticates student credentials and returns JWT bearer token.
POST /api/assessments/submit Persists student assessment answers, computes score, and updates master history.
POST /api/ai/predict Takes student performance features (stu_acc, skill_acc, recent5, speed) and returns predicted correctness probability and adaptive next topic recommendations.

4. Frequently Asked Questions (FAQ)

Is my practice data stored on a remote server?

No. In this frontend version, all assessment attempts, streak days, daily goals, and accessibility preferences are stored locally in your browser's localStorage. No personal data is sent externally.

Can I change my learner category after registration?

Yes! You can change your primary category or toggle individual accommodations at any time in Accessibility Settings or on your Profile Page.

How does the Read-Aloud speech synthesis work?

The platform utilizes the browser's built-in Web Speech API (window.speechSynthesis). It speaks the question and options only when you click the "Speak Question" button. It will never play unexpected audio without student consent.
